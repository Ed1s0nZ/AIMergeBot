## 原始需求与目标

用户希望整体深度优化 AIMergeBot，从小工具升级为项目：React 重构前端，增加登录及产品功能，改善基于 Git 的审计，评估以 Eino 重构 AI Agent。

目前问题：无访问控制；MR 后续提交可能漏审；工具读取的 main 与审计 diff 不一致；模型解析失败可能生成虚构发现；任务和历史记录缺少可靠生命周期。目标是登录用户可管理项目、执行审计、查看可信证据并人工复核，且运行过程可追踪、可恢复。

## 用户场景

- 管理员配置访问与项目；失败时得到明确原因，凭证不暴露给普通用户。
- 用户登录后查看项目和审计任务；无权限时不能读取或操作对应数据。
- MR 更新触发新提交审计；重复事件不产生重复任务；失败可重试。
- 用户打开发现，查看代码位置和证据，记录误报/接受/修复；重跑保留历史复核记录。
- 管理员查看失败或不完整审计，获知覆盖缺口与重试方式，不能误认为“无风险”。

## 约束及失败恢复

- 用户明确约束：React 前端；深度改善审计；Eino 是提出的改造方向。
- 暂无用户指定时间、预算、部署规模或数据库要求。
- 失败应保留阶段、原因与尝试记录；重试不得抹掉历史；审计失败和无发现是不同结果。
- 迁移须提供备份和回退说明；不自动合并 MR 或写代码作为本草案默认范围。
