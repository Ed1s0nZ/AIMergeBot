## 契约与数据流

ProjectConfig新增internal_project bool，yaml/json omitempty，旧省略/false保持GitLab远端ID解释。true仅为DB已有显式绑定项目的引用；不从配置创建binding、不增加ACL、不携带token、不按配置重解释provider。

启动导入迁移到Store.ImportConfiguredProjects一个短写事务：预验证整个批次、拒绝重复ID；legacy项只允许目标ID不存在绑定；已绑定但旧配置仍legacy时ErrConflict并整体回滚，不能先写其他项目。internal_project=true必须有有效既存binding与项目；配置name/enabled/context内容不回写该项目，DB为权威。返回legacy项供现有context导入；内部项目context不能被同ID旧配置覆盖。事务中检查binding及保存，阻止并发绑定窗口。Legacy新项目enabled默认true、既存项目省略enabled保留原值；其余SaveProject取消关联context run及同步outbox语义保持。

SyncProjectConfig导出绑定项目时加internal_project=true；即使损坏binding也不能输出legacy，返回固定同步失败并保留dirty。配置保存后运行中的binding始终DB权威。SaveRepositoryBinding的原CAS事务同时markProjectSync；绑定HTTP成功后Settings存在则尝试SyncProjectConfig，失败返回明确“绑定已保存、配置同步待恢复”，不让调用者以为全回滚。dirty重启先恢复导出；失败不允许旧配置导入。不把JSON未授权输入当远端验证。

main.run只委托ImportConfiguredProjects，并向ImportContextRepositories传返回legacy列表；不重复旧循环。Store.SaveProject抽取已有事务helper，启动用同helper，避免复制取消/同步行为。外部配置文件写在SQLite事务外，generation fencing防止新绑定保存被旧导出标clean；当前同步锁/故障恢复机制保留。导出读取要有一致DB snapshot，不能混用项目列表和binding版本读取造成新内部项目以legacy输出；收集projection使用短读事务，随后文件写入，再按captured generation清dirty。

## 后续内部ID创建（仍需具体F3/API契约）

新增bound项目必须在同一事务分配独立内部ID、创建project及binding；不能先创建enabled且无binding的临时项目让poll走legacy。内部ID用当前max+1并检查溢出，未来同值GitLab legacy导入明确冲突。绑定所需集成scope存在先后依赖：新请求需显式携带expected_integration_revision及选择的集成，管理员以同事务将新内部ID纳入该集成scope并增加revision/配置历史/event，然后创建binding。只增加所请求新项目的scope，不自动创建任何用户ACL；不移除原scope或重置凭据。失效/冲突整体回滚。此创建API将与页面确认说明、Integration原CAS语义一起设计/测试，不用“不支持GitHub”作为永久替代。
