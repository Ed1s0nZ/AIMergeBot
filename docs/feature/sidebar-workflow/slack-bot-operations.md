# Slack 身份绑定与固定提交复审

当前实现支持 Slack slash command 的 form 回调。出站通知与交互命令共用渠道配置，但通知配置完整并不代表已配置交互。其他机器人交互协议仍需单独实现和验证。

## 配置

1. 管理员在「集成与通知」选择 Slack，设置启用项目范围和 HTTPS webhook 地址。
2. 显式替换完整凭据时填写 Slack Signing Secret、应用 A-ID 和工作区 T-ID。保存后只显示是否配置，不回显凭据。普通编辑默认保留凭据。
3. 将 Slack 命令的 Request URL 设置为站点 HTTPS 根地址加页面显示的 `/api/v1/bot-callbacks/slack/<渠道ID>/<版本>/command`。渠道版本变化后需同步 Request URL。
4. 平台 Public URL 须配置为 HTTP(S) origin；生产使用 HTTPS。配置后状态命令提供需登录的证据页面链接，不携带访问令牌，不预览源码。

旧 `/bind` 回调路径仍只完成绑定。保存配置不会发送测试消息或创建审计任务；测试通知须管理员明确操作。

## 用户操作

在「我的机器人绑定」选择当前有项目访问权限的渠道，生成一次性凭据，将 `bind <凭据>` 作为管理员配置的 Slack 命令参数。凭据十分钟有效，重新生成替换旧凭据。平台只存摘要；页面不将令牌保存到 URL 或浏览器持久存储。绑定成功后刷新确认工作区和稳定外部用户 ID。

- `status <任务ID>`：查看固定 HEAD 和任务状态；配置 Public URL 后返回平台证据页链接。
- `reaudit <任务ID> <完整HEAD>`：复审原任务快照。HEAD 必须与原任务一致；原任务须已结束且使用当前审计策略版本。执行不切换最新提交，不修改人工复核结论，不合并 PR。
- 撤销绑定同时撤销该渠道下自己的未用凭据；渠道停用后仍可撤销。撤销不替代取消已入队任务。

身份绑定不授予项目权限。状态查看要求目标、来源和关联仓库当前权限；复审要求目标 operator，以及完整来源/context 权限。项目须启用且目标须属于渠道范围。worker 执行前再查权限，入队后撤权会取消任务。

## 故障与重复请求

- 400：回调格式、媒体类型或大小不合法，检查 slash-command form 配置。
- 403：签名/身份/权限/HEAD/版本/父任务状态等校验拒绝，或已消费签名重放。错误不披露账号或任务是否存在。
- 429：复审容量不足，等待 Retry-After 后重新发起命令。
- 503：复审服务不可用，等待 Retry-After 并检查 worker。

有效签名限制在五分钟时间窗口，并使用持久数据库记录防重放。重复有效新命令会复用同快照 pending/running 任务；同一签名已消费则拒绝。成功响应只确认排队，不代表审计完成；用 status 或平台页面查看结果。

绑定发行/完成/撤销及复审请求记录平台操作者和渠道/任务标识，不保存令牌、签名或回调正文。日志、nonce 与对应状态变更同事务；写入失败不会留下部分任务。
