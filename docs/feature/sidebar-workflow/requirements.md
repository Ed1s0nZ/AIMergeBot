## 问题与目标

现有导航围绕任务历史与配置，用户需要逐个进入审计任务寻找需要处理的问题。目标是从统一入口定位待处理事项，并继续使用原有详情、证据和复核流程。保持 PR/MR 审计及不限制语言的定位。

## 原始默认假设（被本次范围扩展替代）

- ASM-001：本次优先交付待办中心、发现中心和导航分组。独立审计策略、关联仓库、成本、质量评估页面留作后续；现有相关功能入口保留。
- ASM-002：待办是授权范围内的工作队列，不引入负责人分配、通知发送或截止时间。
- ASM-003：发现中心复用现有人工复核语义，不新增自动关闭、自动修复或合并阻断策略。
- ASM-004：交付到功能分支；本次不自动合并 main、不发布版本。

## 非目标

不改变审计模型与证据等级，不增加语言解析器门槛，不将格式化噪音检测混入这次侧边栏迭代，不自动推断问题已修复。

### 待确认的交付边界

- 默认 Git 平台范围：现有 GitLab 加 GitHub。其他 Git 平台通过通用 Webhook 对接，不标记为原生支持。
- 默认管理权限：管理员配置渠道，渠道按项目授权；群消息只含摘要与受权限控制的链接。
- 默认机器人交互：查看证据链接和经过身份绑定的复审；不实现群内直接修改复核结论或自动合并。
- 实现平台适配器与受控协议测试；真实发送验证需要用户配置测试账号/接收人，不能使用已有生产凭据擅自发送。
- 功能分支交付，未收到本次明确合并指令前不自动合并 main 或发布版本。

来源：用户在修复闭环、归并、风险接受、责任人、覆盖说明、合并检查、结果对比、配置诊断建议之后要求“最佳实践优化”。全部建议作为此版本需求快照的新增范围，尚待快照确认。

| ID | 需求 | 验收 |
| --- | --- | --- |
| REQ-016 / AC-014 | 修复闭环：新提交后可复审并保留前后证据。 | 明确区分仍存在、已修复、证据不足；仅未再次发现不能认定修复；旧结论保留原提交身份。 |
| REQ-017 / AC-015 | 关联同一 PR 多次运行的问题，减少重复复核与通知。 | 沿用现有指纹和人工关联；不按标题盲目合并；新严重程度与证据变化仍需提醒，不自动继承风险接受。 |
| REQ-018 / AC-016 | 风险接受记录理由、责任人和到期时间。 | 与误报状态分离；到期重新进入待办并提醒；有变更历史和权限限制，不允许无期限隐藏问题。 |
| REQ-019 / AC-017 | 按项目配置或 CODEOWNERS 推荐责任人。 | 展示匹配来源，无法匹配保持未分配；仓库声明不能授予系统权限；分配规则变更可追溯。 |
| REQ-020 / AC-018 | 展示审计覆盖、跳过文件和预算导致的缺口。 | 统计范围与固定提交一致；失败或部分完成不显示为全部检查通过；新入口复用现有真实覆盖数据。 |
| REQ-021 / AC-019 | 向 GitLab/GitHub 发布可配置合并检查状态。 | 高风险、失败、不完整分别展示；结果绑定准确提交，旧运行不能覆盖新提交状态；默认不启用阻断。 |
| REQ-022 / AC-020 | 对比两次提交或策略的审计结果。 | 展示新增、未再次观察和证据/等级变化；注明范围差异；未再次观察不自动等同已修复。 |
| REQ-023 / AC-021 | 配置诊断覆盖模型、仓库权限、Webhook、邮件及机器人。 | 区分本地配置检查和远端探测；错误脱敏；测试发送需用户主动触发；无凭据时显示未配置。 |

### 现有基础

finding_lifecycle.go 已记录问题指纹、运行出现历史和人工复核历史；NotReobserved 表示未再次观察，不是已修复。finding_associations.go 与 followup-audit.tsx 已有跨运行关联及复审入口。新增需求是在这些基础上补齐工作流，不能重复造一套互不一致的状态。

### 新增默认边界（待确认）

- 风险接受由项目管理员/具备管理权限的人员操作，到期不删除历史记录。
- 自动复审与 Git 检查发布由项目管理员显式启用，默认不改变现有合并规则。
- 配置诊断不执行仓库代码；远端测试与消息发送在页面上由用户主动触发。
- 实现按待办/发现 → 生命周期/覆盖/对比 → 集成与通知 → 策略/统计/诊断推进，各阶段完成仍不代表完整目标完成。
